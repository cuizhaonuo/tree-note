# 账号与服务器存储（accounts-and-server）

**Status:** done（2026-10-11，issues 01–08 全部完成）

## Problem Statement

树形笔记目前是一个没有后端的单人工具：笔记存在浏览器授权的本地文件夹里，只能在那台电脑、那个浏览器（Chrome/Edge）里打开。换一台电脑就看不到自己的笔记，要靠 git 或网盘手动同步。将来还想让其他人也用上这个工具，但现在既没有“用户”的概念，也没有地方存放别人的笔记。

## Solution

把应用部署到一台腾讯云服务器上，笔记全部存在服务器上，在任何一台电脑的浏览器里登录后都能使用。

- 每个用户有自己的账号，只能看到自己的笔记。
- 账号只能由管理员创建，不开放注册。
- 管理员登录后，除了笔记界面，还多一个管理界面，可以创建用户、重置密码、禁用用户，以及查看每个用户的基本信息；但看不到别人的笔记内容。
- 笔记在服务器上仍然是一篇一个 `.md` 文件，格式和原来完全一样。
- 数据每天在服务器上用 git 记录一次历史，并打包上传到腾讯云对象存储（COS）作为异地备份。

目前只有一个用户（作者本人，同时是管理员），但数据和权限从第一天起就按多用户设计。

## User Stories

### 登录与会话

1. 作为用户，我想用用户名和密码登录，这样只有我自己能读写我的笔记。
2. 作为用户，我想在没登录时打开任何页面都被带到登录页，登录后回到笔记界面。
3. 作为用户，我想登录一次之后 30 天内不用再登录，并且每次使用都会顺延，这样日常使用不被打断。
4. 作为用户，我想能主动退出登录，这样在别人的电脑上用完后不会留下登录状态。
5. 作为用户，我想在用户名或密码错误时只看到“用户名或密码错误”，而不提示具体是哪一个错了，这样别人无法试探哪些用户名存在。
6. 作为用户，我想在同一用户名或同一 IP 连续输错 5 次密码后被锁定 15 分钟，这样服务器暴露在公网上时不容易被暴力破解。
7. 作为用户，我想自己修改密码（需要输入旧密码），改完后其他设备上的登录自动失效，这样怀疑密码泄露时可以立即止损。
8. 作为被禁用的用户，我想在下一次请求时就被退出登录并看到“账号已被禁用”，而不是一直以为是网络问题。
9. 作为用户，我想在登录过期后，正在编辑的内容不丢失：提示我重新登录，登录后继续保存。

### 笔记（迁到服务器后保持原有体验）

10. 作为用户，我想登录后直接看到自己的笔记列表，按最近修改时间排序，和原来本地文件夹的体验一样。
11. 作为用户，我想原来所有的键盘操作、树的显示、撤销、折叠、缩放都保持不变，这样迁移后不需要重新适应。
12. 作为用户，我想新建、重命名、删除笔记的行为和原来一样：文件名由标题生成，重名时加 `-2` 之类的后缀。
13. 作为用户，我想每次改动后大约 1 秒自动保存到服务器。
14. 作为用户，我想在界面上看到保存状态（已保存 / 保存中 / 未保存），这样知道内容是否已经安全。
15. 作为用户，我想在断网或服务器暂时不可用时继续编辑，未保存的内容暂存在浏览器里，网络恢复后自动重试保存，这样不会因为网络问题丢失内容。
16. 作为用户，我想在暂存了未保存内容的情况下关闭或刷新页面，再次打开这篇笔记时能恢复这些内容并继续保存。
17. 作为用户，我想在同一篇笔记被另一台设备或另一个标签页改过时，这里的保存被拒绝并提示“这篇笔记在别处被修改过，请刷新”，而不是悄悄覆盖掉另一边的内容。
18. 作为用户，我想全文搜索仍然覆盖我所有笔记里所有结点的文字，点击结果打开对应笔记并选中那个结点。
19. 作为用户，我想在 Chrome、Edge、Firefox、Safari 等电脑上的主流浏览器里都能使用，而不只是 Chrome 和 Edge。
20. 作为用户，我想把原来本地文件夹里的 `.md` 笔记拷到服务器上我的目录后，它们直接出现在笔记列表里，不需要任何格式转换。

### 管理员

21. 作为管理员，我想用和普通用户相同的方式登录，进入的同样是我自己的笔记界面，另外多一个“管理”入口，这样一个账号就够用。
22. 作为普通用户，我想看不到“管理”入口，直接访问管理页面或管理接口时被拒绝。
23. 作为管理员，我想看到所有用户的列表：用户名、角色、状态、创建时间、最后登录时间、笔记数量、占用空间。
24. 作为管理员，我想创建一个新用户（填写用户名、初始密码、角色），然后把初始密码线下告诉对方。
25. 作为管理员，我想在用户名已存在时看到明确的错误提示。
26. 作为管理员，我想重置某个用户的密码，重置后这个用户在所有设备上的登录立即失效。
27. 作为管理员，我想禁用一个用户，禁用后他的所有登录立即失效且无法再登录；也能重新启用他。禁用不删除他的笔记。
28. 作为管理员，我想不能禁用自己，也不能把自己的角色改掉，这样不会把系统锁死到没有任何管理员。
29. 作为用户，我想管理员在应用里看不到我的笔记内容，只能看到数量和占用空间。

### 运维

30. 作为服务器管理者，我想用一条命令行脚本在服务器上创建第一个管理员账号，因为这时还没有任何人能登录管理界面。
31. 作为服务器管理者，我想服务器开机后应用自动启动，崩溃后自动重启。
32. 作为服务器管理者，我想用一条命令完成部署：拉取最新代码、安装依赖、构建、重启服务。
33. 作为服务器管理者，我想服务器上的笔记数据每天自动做一次 git commit，这样误删或改坏内容后能查到历史版本并恢复。
34. 作为服务器管理者，我想笔记数据每天自动打包上传到 COS，并且只保留最近 30 天的备份，这样服务器整个丢失时也能恢复。
35. 作为服务器管理者，我想 COS 的访问密钥只有向这一个存储桶上传的权限，并且只保存在服务器的配置文件里，不进代码仓库。
36. 作为服务器管理者，我想备份失败时能在日志里看到明确的错误，而不是悄悄失败。
37. 作为开发者，我想在本机同时启动前端和后端进行开发，使用一个本地的临时数据目录，不碰服务器上的数据。

## Implementation Decisions

### 架构

- **推翻原 spec 的“没有后端、本地文件夹”**，原因和取舍见 ADR-0001。本地文件夹模式（File System Access API）整体删除，不保留两种模式并存。
- **后端**：Node.js + TypeScript，HTTP 框架用 Hono。选 TypeScript 是为了让服务器直接复用核心模块（格式解析与写回、文件名生成、全文搜索），前后端共用一套逻辑。
- **核心模块不变**：它仍然是不依赖界面、也不依赖存储的纯逻辑模块。前端和服务器都依赖它，它不依赖任何一方。
- **前端**：仍是 Vite + React。原来直接读写本地文件夹的“笔记库”这一层，替换为一个调用服务器接口的客户端，对界面暴露的能力保持不变（列出、读取、新建、写回、重命名、删除笔记）。笔记不再用文件句柄标识，而是用文件名标识。
- **生产环境的请求路径**：浏览器 → Caddy（80 端口，纯 HTTP，通过 IP 访问）→ Node 服务。Node 服务同时提供 `/api/*` 接口和构建好的前端静态文件。以后有了域名，只改 Caddy 配置就能启用 HTTPS。

### 存储

- **笔记**：每个用户一个目录，例如 `<数据目录>/users/<userId>/`，目录下每篇笔记一个 `.md` 文件。文件格式、文件名规则、重名后缀、round-trip 稳定性都和原 spec 一致。数据目录的位置由配置决定。
- **账号和会话**：存在数据目录下的一个 SQLite 文件里，优先使用 Node 自带的 `node:sqlite`，避免需要编译的原生依赖。数据量很小，不需要独立的数据库服务。
- **用户表字段**：id、用户名（唯一）、密码哈希、角色（`admin` 或 `user`）、状态（`active` 或 `disabled`）、创建时间、最后登录时间。笔记数量和占用空间在查询时统计目录得到，不存储。不收集邮箱。
- **会话表字段**：会话 id（随机生成的高熵字符串）、用户 id、过期时间。
- **登录失败记录**：按用户名和按 IP 分别计数，用于锁定。

### 认证

- **服务端 session**：登录成功后下发一个 HttpOnly、SameSite=Lax 的 cookie，内容只有会话 id。暂时用纯 HTTP 访问，所以不加 `Secure` 标记；启用 HTTPS 时再加上。
- **有效期**：30 天，滚动续期。为了避免每个请求都写数据库，剩余有效期少于一半时才续期。
- **失效**：退出登录时删除当前会话。用户修改密码时删除这个用户的其他所有会话。管理员重置密码或禁用用户时，删除这个用户的所有会话。每次请求都检查用户状态，被禁用的用户即使会话还在也一律拒绝。
- **密码哈希**：使用 Node 自带的 `crypto.scrypt`，每个密码配独立的随机盐。和 argon2、bcrypt 强度相当，但不需要原生依赖。
- **锁定**：同一用户名或同一 IP 在 15 分钟内连续失败 5 次，就锁定 15 分钟。锁定期间即使密码正确也拒绝登录，并提示稍后再试。登录成功后清零这个用户名的失败计数。
- **防止系统被锁死**：管理员不能禁用自己，也不能修改自己的角色。
- **首个管理员**：通过服务器上的命令行脚本创建（传入用户名，交互式输入密码），不提供网页上的初始化入口。

### 接口约定

所有接口返回 JSON。未登录返回 401，权限不足返回 403。下面只列出决策相关的部分：

- **会话**：登录、退出、获取当前用户（用户名、角色）、修改自己的密码（需要旧密码）。
- **笔记**（只作用于当前登录用户自己的目录）：
  - 列出笔记：返回文件名和最后修改时间，按修改时间倒序排列；
  - 读取笔记：返回全文和**版本号**；
  - 新建笔记：传入标题和全文，服务器生成不重名的文件名，返回文件名和版本号；
  - 写回笔记：传入全文、**基于的版本号**，以及可选的新标题。如果标题变了，就在同一次操作里完成重命名（规则和原来一样，包括“只差大小写时直接写回原文件”）。如果服务器上的当前版本和传入的版本号不一致，返回 **409**，不写入；
  - 删除笔记；
  - 全文搜索：在服务器上对这个用户的所有笔记执行核心模块的搜索，只返回匹配结果。
- **版本号**：取文件内容的哈希值。外部改动（比如手动拷进来的文件、git 恢复）也会被正确识别为“版本已变化”。
- **文件名校验**：服务器只接受符合文件名规则的名字（不能包含路径分隔符或 `..`，必须以 `.md` 结尾），防止通过接口读写用户目录以外的文件。
- **管理**（仅限管理员）：列出用户（含统计信息）、创建用户、重置密码、禁用和启用用户。**不提供任何读取其他用户笔记内容的接口。**

### 前端行为

- 新增登录页、修改密码界面，以及管理员才能看到的管理页面。
- 任何接口返回 401 时，前端保留当前未保存的内容，弹出登录界面；重新登录后继续保存。
- **自动保存**：防抖时间仍为约 1 秒，每次保存都带上基于的版本号。
  - 保存失败（网络错误或 5xx）时，把未保存的全文按“用户 + 文件名”暂存到 localStorage，界面显示“未保存”，然后按退避间隔自动重试。重试成功后清除暂存。
  - 打开一篇笔记时，如果发现 localStorage 里有它的暂存内容，就恢复暂存内容，并立即尝试保存。
  - 收到 409 时停止自动保存，提示“这篇笔记在别处被修改过，请刷新”。暂存内容保留，不自动丢弃。
- **浏览器支持**：电脑上的主流浏览器（Chrome、Edge、Firefox、Safari）。不再依赖 File System Access API。

### 部署与运维

- **服务器**：腾讯云北京地域，Ubuntu 22.04，4 核 4G。暂时通过公网 IP 用纯 HTTP 访问；只用 IP 访问不需要 ICP 备案。需要在腾讯云安全组里放行 80 端口。
- **运行方式**：直接在系统上安装 Node 和 Caddy，应用由 systemd 管理（开机自启、崩溃后自动重启），不使用 Docker。Node 服务只监听本机端口，只有 Caddy 对外开放。
- **部署**：代码托管在 GitHub。服务器通过它自己配置好的代理访问 GitHub。部署脚本在服务器上依次执行拉取代码、安装依赖、构建、重启服务。
- **配置与密钥**：数据目录、监听端口、COS 存储桶名称和地域、COS 密钥等，都放在服务器上的一个环境配置文件里，由 systemd 加载。这个文件不进代码仓库。
- **每日备份**（由定时任务执行）：
  1. 把数据目录（包括 SQLite 文件）做一次 git commit，没有变化就跳过。提交前先用 SQLite 的备份机制导出一份一致的数据库副本，避免提交写到一半的文件；
  2. 把数据目录打包，上传到 COS 的私有存储桶，用日期命名；
  3. 存储桶上配置生命周期规则，自动删除 30 天前的备份；
  4. 任何一步失败都以非零状态退出，并把错误写入系统日志。
- **COS 权限**：使用腾讯云 CAM 子用户的密钥，这个子用户只有向这一个存储桶上传对象的权限。存储桶设为私有读写。
- **需要人工完成的步骤**（SSH 登录、安全组、CAM 子用户、存储桶生命周期规则、填写密钥、创建首个管理员）用交互式向导脚本引导完成。

### 实施顺序

1. 服务器存储：后端笔记接口 + 前端改为调用接口（先不加登录，只在本机开发）。
2. 登录与会话，以及用命令行创建管理员。
3. 部署上线。
4. 管理界面。
5. 每日备份（git commit + COS）。

## Testing Decisions

- **好的测试只测外部行为**：给定请求，断言响应和数据目录里的结果，不断言内部实现。这和原 spec 测试核心模块的原则一致。
- **核心模块**：继续沿用现有的 Vitest 测试（格式、命令、导航、搜索等），这次基本不改动。
- **新增一个测试切入点：服务器的 HTTP 接口**。用 Hono 的进程内请求能力直接调用应用，不启动真实的端口。每个测试使用一个临时数据目录和一个全新的 SQLite 文件。需要覆盖的内容：
  - 认证：登录成功和失败、统一的错误提示、锁定与解锁（时间可注入，不真的等待 15 分钟）、退出、会话过期和滚动续期、修改密码后其他会话失效、被禁用后立即失效；
  - 权限：未登录返回 401，普通用户访问管理接口返回 403，用户之间的笔记互相隔离（A 无法通过任何文件名读到 B 的笔记）；
  - 笔记：列出、读取、新建（重名后缀）、写回、带重命名的写回（包括只差大小写的情况）、删除、文件名校验（`..`、路径分隔符等）、版本冲突返回 409、外部修改文件后版本号随之变化；
  - 搜索：只搜索当前用户自己的笔记；
  - 管理：创建用户（含重名）、重置密码、禁用和启用、不能禁用自己、列表里的统计信息正确、没有任何途径读到其他用户的笔记内容。
- **自动保存的状态逻辑**（暂存、重试、遇到 409 时停止、打开笔记时恢复暂存）尽量写成不依赖 React 的纯逻辑，用 Vitest 测试。网络请求和 localStorage 通过参数注入。
- **不写单元测试的部分**：Caddy、systemd、部署脚本、备份脚本、前端界面。靠每个任务的验收标准手动验证。
- 现有测试可以参考的写法：核心模块的 `*.test.ts`。

## Out of Scope

- ~~HTTPS 和域名~~（实施中已提前做了：见 Further Notes）。
- 公开注册、邀请链接、找回密码、邮件发送。
- 管理员查看、导出其他用户的笔记内容。
- 删除用户（目前只做禁用）。
- 用户的显示名、邮箱、头像等额外资料。
- 手机端（只读浏览列为以后可能做的事），以及触屏编辑。
- 在界面上导入本地 `.md` 文件（已有笔记由作者用 `scp` 一次性拷到服务器）。
- 保留本地文件夹模式。
- 实时协同编辑；同一篇笔记的冲突只做“拒绝并提示刷新”。
- Docker、GitHub Actions 自动部署。
- 原 spec 里已经列为不做的其他内容，仍然不做。

## Further Notes

- 这份 spec 取代原 spec（`.scratch/tree-note/spec.md`）中关于平台、无后端、本地文件夹存储、浏览器限制和同步的决策；其他决策（领域模型、文件格式、键盘映射等）仍然有效。
- 已有的本地笔记迁移方式：部署并创建账号后，用 `scp` 拷到服务器上该用户的笔记目录。
- 实施时还需要作者提供两项信息：服务器的公网 IP 和登录方式（部署那一步），以及 COS 存储桶的域名（包含桶名和地域，备份那一步）。COS 密钥由作者在服务器上亲手填写，不在对话里传递。
- **实施中与上文不一致的地方**：部署时已提前启用了 HTTPS（提交 a63a1d2）。Caddy 以 `treenote.site` 提供服务，自动签发证书，`www` 和裸 IP 都重定向到这个域名；Caddy 报告请求来自 HTTPS 时，会话 cookie 会加上 `Secure`。上文中“纯 HTTP、通过 IP 访问、不加 `Secure`”的描述是当时的决策，以这里为准。
