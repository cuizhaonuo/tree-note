# 笔记从本地文件夹迁到服务器存储

树形笔记最初是一个没有后端的单人工具：笔记存在浏览器通过 File System Access API 授权的本地文件夹里，同步交给用户自己用 git 或网盘完成。现在需要多人使用（每人有自己的账号和笔记，由管理员管理账号），并且希望在任何一台电脑上都能访问，所以决定增加一个 Node.js 后端，部署在一台腾讯云服务器上。笔记全部存在服务器上，**整体删除本地文件夹模式**。在服务器上，笔记仍然是一篇一个 `.md` 文件，按用户分目录存放；账号和会话存在 SQLite 里。

## Considered Options

- **服务器存储与本地文件夹两种模式并存**：没有采用。两套存储要同时维护，而“本地模式”下既没有用户，也没有管理员，和这次的目标相互矛盾。
- **服务器只管账号，笔记仍在本地**：没有采用。这样登录保护不了任何东西，管理员也无从管理。
- **笔记改存数据库**：没有采用。保留 `.md` 文件，可以原样复用已有的文件格式约定、round-trip 稳定性和全部测试；文件仍然人能直接读懂，并且可以直接用 git 记录历史、打包备份。
- **后端用 Python**：没有采用。后端用 TypeScript，才能直接复用核心模块（格式解析与写回、文件名生成、全文搜索）。

## Consequences

- 原 spec 里“没有后端”“只支持 Chrome 和 Edge”“多设备同步不做”这几条决策失效，详见 `.scratch/accounts-and-server/spec.md`。不再依赖 File System Access API 以后，Firefox 和 Safari 也能使用。
- 数据不再天然在用户自己手里，因此必须做备份：每天在服务器上 git commit 一次，并上传到腾讯云 COS。
- 自动保存从写本地文件变成了网络请求，因此需要处理断网和多设备同时编辑：写入时带版本号，冲突时拒绝写入并提示刷新，未保存的内容暂存在浏览器里。
